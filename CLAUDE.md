# Switchback — Claude Code notes

Navigation-first hiking app for iPhone (SwiftUI, iOS 26, Liquid Glass). Full product spec: docs/PRD.md.

## Build

The Xcode project is generated — never edit `Switchback.xcodeproj` directly; edit `project.yml` and run `xcodegen generate`. New Swift files under `Switchback/` are picked up automatically on regeneration.

```sh
xcodegen generate
xcodebuild -project Switchback.xcodeproj -scheme Switchback \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build
```

## Architecture decisions

- **Persistence:** SwiftData. Models in `Switchback/Models/`. `TrackPoint` and `Waypoint` are Codable value types stored as attributes on `Route`/`Activity`, not separate @Model classes.
- **Maps:** MapKit as a placeholder; the PRD mandates Mapbox once tokens are set up (see README). Keep all map-rendering code inside `Features/Map/` so the swap stays contained.
- **State:** `@Observable` classes (`LocationService`, `RecordingSession`) injected via `.environment()`. No third-party architecture frameworks.
- **Navigation:** never use a SwiftData `@Model` instance as a `NavigationLink` value — the path snapshot can outlive the model and crash in `PersistentModel.getValue` on property access. Pass `route.persistentModelID` and resolve via `modelContext.model(for:)` in `navigationDestination(for: PersistentIdentifier.self)`. Eager `NavigationLink(destination:)` is also avoided in lists (builds every row's destination up front).
- **Units:** store meters internally, format for display only via `Format` (Services/Formatters.swift) which respects the user's locale.

## Product guardrails (from PRD)

- No popularity features: no likes, followers, trending, star ratings, or popularity-based sorting — don't add them even as placeholders.
- GPX imports default to private routes (`RouteType.personal`).
- Downloads and completed activities are separate sections, never mixed.
- Summits are detected from completed activity tracks, never manually marked.
- Map stays the primary visual element; keep UI chrome minimal and floating (Liquid Glass).

## Summit database

`Switchback/Resources/summits.sqlite` is read-only reference data (USGS GNIS summits, elevations from the Copernicus GLO-90 DEM), regenerated by `python3 tools/build_summit_db.py --national`. It is queried through `SummitDatabase` (raw SQLite3, no third-party dependency) — never put reference summits into SwiftData; the SwiftData `Summit` model stores only the user's visits. Summit detection (`SummitDetector`) and the map's summit markers both query this database by bounding box. Future: prominence data (Kirmse dataset) to filter sub-summits, and international regions as downloadable extracts.

## Color system

Brand palette lives in `Switchback/Assets.xcassets` with light/dark variants, exposed via `Color` extensions in `App/Theme.swift` (`.brandPrimary` olive, `.brandSage`, `.brandNavy`, `.brandSky`, `.routeAccent` orange). Rules:

- `.routeAccent` (#EE792F) is functional only: route lines, active recording, off-route alerts. Don't use it for decoration, and never put white text on it — use `.routeAccentText`.
- Route polylines are always drawn cased: white 6pt under accent 3.5pt, so they survive satellite imagery and dark terrain.
- Blue linework on the map is reserved for water; never draw routes or tracks in blue/navy.
- Don't add new hardcoded colors in views; add a colorset with both appearance variants and extend Theme.swift.
